    Linear solves and diagnostics¶

    Solver choice and solve diagnostics for the inference's linear systems.

    Every tension and pressure of this package is the solution of a linear least-squares system. Small systems are solved densely (scipy.linalg.lstsq), exactly; large ones sparsely (lsqr, or a sparse direct factorisation), because a dense system grows as the product of its dimensions in memory and as their cube in time: the Young-Dupre system of a 1 866-cell tissue is 49 984 x 11 746, 4.7 GB dense, and at 10 000 cells it would be some 120 GB.

    This module holds what the public entry points (infer_tensions*, infer_pressures*, infer_forces) pass down to every solve:

    • solver: "auto" (the default) solves a system densely below sparse_threshold unknowns and sparsely at or above it; "dense" and "sparse" force one path whatever the size. Below the threshold, "auto" is bitwise the dense solve. Forcing "dense" on a system whose dense form would not fit in the memory available emits a DenseSolveMemoryWarning with the estimate, before anything is allocated. The tension methods Equilibrium, Variational and ForceBalance* have no sparse path: they are solved densely under "auto", and "sparse" raises ValueError for them. A sparse lsqr solve that does not converge falls back to the dense one with a SparseSolveFallbackWarning (or, when the dense one cannot fit in memory, returns lsqr's last iterate with that warning).
    • sparse_threshold: the number of unknowns at which "auto" switches (default foambryo.junction_graph.SPARSE_SOLVE_MIN_UNKNOWNS, 2 000). What counts as "unknowns" is the number of columns of the system the dense path would assemble: the interfaces of one junction-graph component for a tension solve, the materials for a Laplace pressure, the interfaces plus the cells for the variational pressure. One exception: the variational pressure of a cropped mesh is solved densely up to foambryo.pressure_inference.DENSE_CROP_PRESSURE_MAX_ENTRIES matrix entries under "auto", whatever sparse_threshold is.
    • diagnostics: False (the default: nothing is computed and each entry point returns its usual values), True (one SolveRecord per solve: solver, shape, rank, residual norm, condition number, time) or "spectrum" (also the extreme singular values of the large, sparse systems, by scipy.sparse.linalg.svds, at a measured extra cost). With diagnostics on, each entry point returns one more value, a SolveDiagnostics, last; save_solve_diagnostics writes it to a JSON file (the scalars) and an NPZ file (the singular values).

    They are keyword-only on every entry point that takes them, and an invalid value raises ValueError (validate_solve_options). A lower-level function called directly (for example infer_tensions_young_dupre_local) uses the options in force, the defaults outside any entry point; solve_options puts others in force around such a call.

    What the condition numbers are. On a dense least-squares solve, the 2-norm condition number s_max / s_min from the singular values scipy.linalg.lstsq computes anyway (free; inf when the smallest is zero). On an lsqr solve, lsqr's own running estimate of the Frobenius-norm condition number ||A||_F ||A^+||_F (free; an estimate, and an over-estimate of the 2-norm one by up to a factor n). On a sparse direct solve, the 1-norm condition number estimated from the factorisation (Hager-Higham, scipy.sparse.linalg.onenormest; cheap). The source is recorded beside every number: the three are not the same quantity.

    How the options travel. A public entry point sets them in a context variable for the duration of its call, and the solve helpers read it, so the options reach every solve without threading an argument through each builder. The context is per thread and per asynchronous task (contextvars); outside any entry point the defaults apply.

    DenseSolveMemoryWarning ¶

    Bases: UserWarning

    A dense solve was forced on a system whose dense form exceeds the memory available.

    Emitted before anything is allocated, with the estimate, so that the caller can stop the run (turn it into an error with warnings.simplefilter("error", DenseSolveMemoryWarning)). Only solver="dense" emits it: "auto" never chooses the dense path for a large system.

    extreme_singular_values ¶

    extreme_singular_values(operator: spmatrix | sparray, *, symmetric_positive: bool = False) -> tuple[NDArray[np.float64] | None, float, str | None]

    The largest and smallest SPECTRUM_EXTREME_VALUES singular values of a sparse operator.

    The largest by scipy.sparse.linalg.svds (ARPACK, which="LM"). The smallest first by svds with which="SM"; if ARPACK does not converge within SPECTRUM_MAX_ITERATIONS, by shift-invert at zero (eigsh(..., sigma=0), a sparse LU factorisation) of the operator itself when it is symmetric positive (symmetric_positive: its singular values are its eigenvalues) or of the normal matrix A^T A otherwise. The normal matrix squares the condition number, so those values are accurate only down to about 1e-8 of the largest; the note says which route gave them. Never raises on a failure: what is missing is said in the note.

    Returns:

    Name Type Description
    tuple NDArray[float64] | None

    the values in decreasing order (None if none were obtained), the seconds spent, and
    float

    a note (None when both ends came from svds).
