    Validation¶

    Validation and benchmarking tools: the unified force-balance operator and mesh checks, on raw mesh arrays.

    The unified force-balance operator (the gradient of the capillary energy with respect to the mesh vertices, one column per unknown), its solvers and diagnostics, so that it can be tested and benchmarked within foambryo; the ForceBalance* tension methods are built on it. The test suite compares these functions with an independent reference implementation of the same algorithms (tests/reference/force_balance_reference_implementation.py). These functions check and benchmark an inference; they are not an inference method of their own.

    A mesh here is three arrays, (V, F, regions): vertices (nv, 3), triangles (nf, 3) (vertex indices) and the two regions each triangle separates, (nf, 2), the medium being region 0 by default (foambryo.validation.mesh_io); foambryo.validation.force_balance builds and solves the operator on them.

    constrained_covariance ¶

    constrained_covariance(m: NDArray[float64], anchors: list[NDArray[float64]] | NDArray[float64], sigma_f: float) -> NDArray[np.float64]

    Covariance of the solve_constrained estimator under i.i.d. force-balance noise.

    Model: the vertex force residual M @ beta is not exactly zero but epsilon ~ N(0, sigma_f^2 I), so beta_hat is a constrained generalised-least-squares estimator. Its covariance is the usual GLS covariance projected onto the constraint's null space,

    Sigma = sigma_f^2 (H^-1 - H^-1 A^T (A H^-1 A^T)^-1 A H^-1),     H = M^T M,

    which is singular along every constraint direction — variance exactly zero in the gauge that was fixed by hand, which is the correct statement: the overall tension scale is a convention, not a measured quantity. This is the error bar that belongs with the KKT solve, and it needs no prior; contrast map_estimate, whose posterior covariance is non-singular only because the prior supplies the missing information.

    Honest caveat: geometric noise on a good mesh is correlated between neighbouring vertices, since they share triangles, so an i.i.d. epsilon understates the true uncertainty. Use these as relative, comparable error bars across interfaces, not as calibrated absolute ones.

    effective_surface_tensions ¶

    effective_surface_tensions(m: NDArray[float64], ni: int, nj: int, mean_tension: float = 1.0) -> tuple[NDArray[np.float64], NDArray[np.float64], float]

    Ask which surface tensions balance the mesh, fixing nothing but the overall gauge.

    This is the surface-tension analogue of the effective-line-tension check (keep the true surface tensions and ask which line tensions balance the mesh), which detects a factor on a subset of interfaces (for example, some line tensions encoded at half their value by the program that generated the mesh) — a defect in the data, not in the inference. Here the harness operator carries no line-tension block (beta = (gamma, p), by design), so the same question is asked of the surface tensions directly: solve

    min ||M beta||^2   subject to   mean(gamma) = mean_tension

    and compare gamma to nominal. Only ratios are physical, so the constraint is a gauge choice, not a physical input — without it beta = 0 is the trivial minimiser. A comparison of the returned tensions against nominal ones is therefore only meaningful after gauge matching (see foambryo_benchmarks.metrics.effective_tension_ratios in the source repository).

    The only constraint imposed is the mean surface tension, because the harness operator has no line block; with a line block, block_anchors gives a constraint for each tension block. nj > 0 is accepted here only so the residual is reported consistently, and the caller is expected to pass nj = 0.

    Type Description

    tuple[NDArray[np.float64], NDArray[np.float64], float]: (gamma_eff, p_eff, residual_fraction), where residual_fraction is ||M beta_eff|| / ||M_gamma gamma_eff|| — the force left unbalanced once the tensions themselves are free (rho_free). It is the ratio at the minimiser of ||M beta|| under the gauge, not the minimum of the ratio itself, so it is close to, but not strictly, the lowest value residual_at's rho can take at any given tensions. rho far above it means the nominal tensions are wrong; both being large means the mesh is not an equilibrium of any tensions at all.

    map_estimate ¶

    marginalise_pressures ¶

    marginalise_pressures(m: NDArray[float64], ni: int, nj: int = 0) -> tuple[NDArray[np.float64], NDArray[np.float64]]

    Eliminate the pressure block in closed form, keeping the tension columns.

    For any fixed tensions the pressures that minimise ||M beta||^2 are unique (when M_p has full column rank) and given by p* = -M_p^+ (M_gamma gamma + M_t t). Substituting them back leaves

    min ||P_perp [M_gamma | M_t] (gamma, t)||^2,     P_perp = I - M_p M_p^+,

    an exactly equivalent problem in the tensions alone — this is block elimination of a quadratic form, not an approximation, so any constraint acting only on the tension columns (the mean-tension gauge) gives the same tensions from the reduced and the joint problem. The test test_marginalised_and_joint_solves_agree in tests/test_force_balance_inference.py checks this numerically.

    P_perp is applied through a thin QR factorisation of M_p rather than by forming the 3nv x 3nv projector, which would be a ~9 GB dense array on a 20 000-vertex mesh.

    Parameters:

    Name Type Description Default
    m NDArray[float64]

    The force-balance operator.

    		 required
    ni int

    Number of interfaces (surface-tension columns).

    		 required
    nj int

    Number of junctions (line-tension columns). Defaults to 0, the harness-default operator M = [M_gamma | M_p].

    		 0

    Returns:

    Type Description
    tuple[NDArray[float64], NDArray[float64]]

    tuple[NDArray[np.float64], NDArray[np.float64]]: (reduced, pressure_map). reduced is P_perp [M_gamma | M_t], shape (3nv, ni + nj); pressure_map recovers the eliminated pressures as p = pressure_map @ (gamma, t), shape (n_cells, ni + nj).

    residual_at ¶

    residual_at(m: NDArray[float64], ni: int, nj: int, gamma: NDArray[float64], t: NDArray[float64]) -> float

    Fraction of the surface-tension force left unbalanced once pressures are fitted.

    This is the equilibrium residual rho: the norm of the force left over at the given tensions once the best pressures are fitted, relative to the norm of the surface-tension force. With b = M_gamma @ gamma + M_t @ t, the best pressures are p* = -M_p^+ @ b and rho = ||b + M_p @ p*|| / ||M_gamma @ gamma|| = ||P_perp @ b|| / ||M_gamma @ gamma||, with P_perp = I - M_p M_p^+ the projector orthogonal to the pressure column space, computed here via an explicit least-squares fit of the best pressures rather than forming P_perp directly (equivalent, cheaper). rho ~ 0 means the mesh is at equilibrium at the given (gamma, t).

    residual_force_field ¶

    residual_force_field(m: NDArray[float64], ni: int, nj: int, gamma: NDArray[float64], t: NDArray[float64]) -> NDArray[np.float64]

    The per-vertex residual force whose norm residual_at reduces to rho.

    solve_constrained ¶

    solve_constrained(m: NDArray[float64], anchors: list[NDArray[float64]] | NDArray[float64], targets: NDArray[float64]) -> NDArray[np.float64]

    anchors is a list of constraint vectors (e.g. the mean of a block, see block_anchors). The system solved is [[2 M^T M, A^T], [A, 0]] @ (beta, lambda) = (0, targets), with A the stacked anchors.     check_label_orientation_convention ¶

    check_label_orientation_convention(v: NDArray[float64], f: NDArray[int64], regions: NDArray[int64], exterior: int = 0) -> dict

    Check that a mesh's triangle winding agrees with its label column order.

    foambryo requires each triangle's right-hand-rule normal to point away from its first-listed region and into its second (see foambryo.dcel._normalize_label_order). That tie between winding and label order cannot be checked from the labels — sorted label columns are neither necessary nor sufficient — so this checks its geometric consequence instead: every bounded cell must enclose a positive volume.

    Use this once on any mesh from a source other than dw3d (a simulation, a hand-written .rec, or a mesh whose label columns were sorted by a tool that did not reorient the triangles). Without it the failure is silent: compute_volume_cells simply returns negative volumes and everything downstream consumes them.

    Assumes a closed mesh. An open or cropped mesh will report non-positive volumes for the cells it truncates, which is a limitation of the check and not a defect in the mesh; n_nonpositive_cells and the returned volumes let a caller judge which case it is looking at.

    Find triple lines: edges carrying three interfaces on exactly three incident triangles.

    An edge is admitted as a genuine triple line only under the rule mesh_integrity already documents and enforces as triple_line_ok: three distinct region labels (regions_per_edge == 3), spanning three distinct interfaces (interfaces_per_edge == 3), on exactly three incident triangles (triangles_per_edge == 3) -- not merely three region labels.     mesh_integrity ¶

    mesh_integrity(v: NDArray[float64], f: NDArray[int64], regions: NDArray[int64]) -> dict

    Structural integrity report for a multimaterial mesh.

    Implements the dataset-integrity check — no dangling vertex references, and every triple line shared by exactly 3 interfaces — and reports the surrounding edge statistics that say how a mesh fails when it does.

    intact is deliberately narrow: exactly those two conditions. Everything else (open boundary edges, quadrijunction edges, non-manifold interface edges, degenerate or duplicated triangles) is reported separately, because those are mesh-quality facts rather than integrity failures. In particular quadrijunction edges are expected meshing artifacts, not corruption (in a dry foam exactly three films meet along an edge, so a valence-4 edge is an artifact of discretisation).

    Edge terminology, all keyed by the number of distinct region labels appearing on the triangles incident to an edge. This region-label count alone is only a classification, not a validity check: list_junctions uses it to name candidate triple-line edges but, like this function's own n_bad_triple_lines below, only admits one once it also carries three interfaces on exactly three incident triangles (triple_line_ok). A non-manifold edge with three region labels but a fourth incident triangle is malformed, and is left out of the tension system.

    • 1 region: an edge interior to a single interface's triangulation;
    • 2 regions: an interface edge;
    • 3 regions: a triple-line edge — the physical Plateau junction;

    • = 4 regions: a quadrijunction edge.

    A triple-line edge spanning regions {a, b, c} must carry all three interfaces (a,b), (a,c), (b,c), one triangle each. Fewer means the junction is malformed: the operator would then assemble a force balance for a junction that is not one.

    signed_cell_volumes ¶

    signed_cell_volumes(v: NDArray[float64], f: NDArray[int64], regions: NDArray[int64]) -> dict[int, float]

    Divergence-theorem volume per region, with foambryo's sign convention.

    Accumulates +det([v0, v1, v2]) / 6 into each triangle's first-listed region and -det(...) / 6 into its second — the same rule as foambryo.geometry.compute_volume_cells, applied to raw arrays so it can be run on a mesh file before building a DcelData.

    The result is invariant under DcelData's label-order normalisation (swapping a row's two labels also reverses its winding, which negates det, so the contribution is unchanged), and it was verified equal to DcelData.compute_volumes_cells() on benchmarking-dataset/000_mesh.rec to floating-point precision.

    A correctly-wound closed mesh gives a positive volume for every bounded cell and a negative one for the unbounded exterior label, whose faces are all wound inward from its point of view.
